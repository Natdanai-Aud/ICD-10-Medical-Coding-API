# ICD-10 Medical Coding API

Read-only REST API for hospital information systems (HIS): ICD-10 WHO 2016 code
lookup, hierarchy and free-text search, with case examples from the Thai Standard
Coding Guidelines 2017.

## Scope

- Lookup a code, its ancestors, children, notes, dagger/asterisk flags.
- Batch lookup (up to 500 codes) and validation for claim/coding screens.
- Search across code titles and the WHO alphabetical index (60,400 index terms).
- Chapter → block → category → subcategory hierarchy.
- Case examples from the Thai coding guideline (OCR pipeline included).
- No PHI is accepted or stored. Requests contain codes and search terms only.

Out of scope: AI coding suggestions, rule engines, cross-standard mapping.

## Dataset

| Source | Content | Count |
|---|---|---|
| ICD-10 WHO 2016 Vol. 1 (Tabular list) | chapters / blocks / codes | 22 / 265 / **12,187** |
| — three-character categories | A00 … U99 | 2,049 |
| — four-character subcategories | incl. shared subdivisions | 10,138 |
| Vol. 3 (Alphabetical index) | index terms | **60,400** |
| — resolved to a tabular code | | 8,816 (99.99%) |
| — dangling reference in WHO source | `B12` (real code is `D51`) | 1 |
| Guideline 2017 | case examples | OCR pipeline (see below) |

The four-character codes that WHO prints once for a family of categories
(`E10–E14`, `F10–F19`, `K25–K28`, `V01–V06`, …) are expanded programmatically;
without this, common codes such as `E11.9` would be missing.

## Quick start (Windows / Linux, local Python)

Requirements: Python 3.12, `uv`, Docker (for PostgreSQL), and the three PDFs in `pdf/`.

```bash
uv sync
docker compose -f docker/compose.yaml up -d db
uv run icd10 import-icd          # parse PDFs + load PostgreSQL (~3 min)
uv run icd10 serve --reload      # http://127.0.0.1:8000/docs
```

Re-running `import-icd` replaces the active dataset atomically and keeps the old
version rows until the new load commits.

## Docker (API + database)

```bash
docker compose -f docker/compose.yaml up -d --build
# one-off import inside the api container
docker compose -f docker/compose.yaml exec api icd10 import-icd
```

The API container serves `http://localhost:8000`.

## API surface

| Method | Path | Purpose |
|---|---|---|
| GET | `/v1/health/live`, `/v1/health/ready` | probes |
| GET | `/v1/meta` | active dataset + licence notice |
| GET | `/v1/chapters` | 22 chapters with block counts |
| GET | `/v1/chapters/{id}/blocks` | blocks in a chapter |
| GET | `/v1/codes/{code}` | code detail, ancestors, children, notes |
| GET | `/v1/codes/{code}/children` | direct children |
| GET | `/v1/codes/{code}/ancestors` | breadcrumb |
| POST | `/v1/codes/lookup` | batch lookup (`{"codes": [...]}`) |
| POST | `/v1/codes/validate` | validate + parent/chapter |
| GET | `/v1/search?q=...` | ranked full-text + trigram search |
| GET | `/v1/autocomplete?q=...` | typeahead |
| GET | `/v1/examples` | guideline cases (after OCR import) |
| GET | `/v1/export/codes.csv` | full snapshot for HIS caching |

`GET /openapi.json` and `/docs` are generated by FastAPI. The committed
`ICD-10 Medical Coding API.json` is produced by:

```bash
uv run icd10 export-openapi --output "ICD-10 Medical Coding API.json"
```

## Configuration

Environment variables (`.env` is loaded automatically):

| Variable | Default | Notes |
|---|---|---|
| `DATABASE_URL` | `postgresql+asyncpg://icd10:icd10@localhost:5432/icd10` | |
| `AUTH_MODE` | `off` | `off` or `api_key` |
| `API_KEYS` | empty | comma-separated keys; required when `api_key` |
| `ALLOWED_IPS` | empty | comma-separated IPs/CIDRs; empty = any |
| `MAX_BATCH_LOOKUP` | `500` | |
| `TESSERACT_CMD` | UB Mannheim path | OCR only |

Auth uses `X-API-Key`; there is deliberately no OAuth (HIS-to-HIS integration).

## Search behaviour

- Exact code and code prefix matches rank first.
- English full-text search over titles and inclusion terms (`tsvector` + GIN).
- Trigram similarity over the alphabetical index (`pg_trgm`), so typos and
  partial terms still resolve. Index terms are mapped to their tabular code.
- Thai search matches the Thai case-example text once the OCR import is loaded;
  code titles are English-only by design.

## Data pipeline

```
pdf/Vol1 ── pdftotext -layout ──► parse_tabular.py ──► 22 chapters / 265 blocks / 12,187 codes
pdf/Vol3 ── PyMuPDF coordinates ─► parse_index.py ───► 60,400 index terms
                                          │
                                          ▼
                                    load.py (PostgreSQL)
pdf/Guideline 2017 ── Tesseract + OpenCV ─► parse_cases.py ─► case_example tables
```

QA gates enforced by tests:

- 22 chapters, 265 blocks, 2,049 categories, 10,138 subcategories.
- No parser warnings; every index code resolves except WHO's own dangling `B12`.
- Shared subdivisions present (`E11.9`, `F10.0`, `V01.9`, …).
- API contract tests (lookup, hierarchy, search, batch, validation, CSV).

## Guideline OCR (case examples)

`Guideline 2017.pdf` is a 300 dpi JBIG2 scan; its text layer is only a rotated
watermark, so text extraction is useless. The OCR pipeline:

1. Render pages at 300 dpi (`PyMuPDF`).
2. `pytesseract` with `tha+eng` (`tessdata_best` for Thai).
3. Detect table grid lines with OpenCV; OCR each cell; force `eng` +
   `A-Z0-9.` whitelist for the code column.
4. Parse `ตัวอย่างที่ X-Y`, scenario text, and principal/other/external-cause rows.
5. Resolve each code against the tabular dataset; unresolved codes are kept with
   `code_status=unresolved` (Thai ICD-10-TM codes may not exist in WHO 2016).
6. Manual review report for every extracted code (target 100% review).

Install Tesseract 5 + Thai data on Windows:

```powershell
winget install -e --id UB-Mannheim.TesseractOCR
# download tha.traineddata (tessdata_best) into the Tesseract tessdata folder
```

Status: pipeline scaffolding is present; OCR accuracy spike and the full 463-page
run are the remaining Phase 3 work before `/v1/examples` returns data.
